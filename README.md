### Overview
Configured a private internal LAN "192.168.10.0/24", and a DMZ subnet "192.168.11.0/24" which has multiple hosts like windows 7, kali and metasploitable. 
Established routing, default gateways, and firewall filtering policies to keep watch of internal subnet and outbound internet traffic.

### Key elements of learning
learning least privilege by only permitting:
* ICMP for path diagnostics
* UDP port 53 for external DNS name resolution
* TCP port 443 for encrypted web browsing
* TCP port 80 to expose specific web services between the DMZ and LAN.
Validating service accessibility using network tools such as "telnet ip 80" with raw HTTP request "GET /" and active service enumeration using "nmap ip".

### Key difficulties
The only issues ive had was that first, hosts on the "192.168.11.0/24" subnet didnt have default routes and "8.8.8.8" nameserver entries in "/etc/resolv.conf", resulting in unreachable external hosts.
I fixed this by just checking the resolv.conf file on every linux based device and changing the name server. 

Second issue was that pfsense in "Firewall/Rules/OPT1" had a default rule "IPv4 TCP/UDP - description: DMZ to ubuntu" which was overriding the required "IPv4 ICMP Any" rule, causing the windows 7 to not be able to ping 8.8.8.8 or access google.com. 
I fixed this by just deleting the rule.
